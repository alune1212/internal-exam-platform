# macOS 正式考试 UAT 与证据清单

当前本机最小部署的首次验收结果已经记录。固定版本、入口、运行命令和范围见
[`docs/minimal-macos-deployment.md`](minimal-macos-deployment.md)，逐项实测结果见
[`docs/handoff.md`](handoff.md)。这些结果对应现网 `47b4c17`，不代表 v1.0.0 源码候选的检查、CI 或发布已经通过。本页保留可复用的验收动作、回传证据和停止条件，避免重复维护结果流水。

## 可复用的验收动作

### 端口与服务

- [ ] 从应考人员设备打开当前候选入口，确认首页和健康检查可用。
- [ ] 在 Mac 本机打开操作员入口，确认管理登录可用。
- [ ] 在 Mac 本机执行 minimal 部署文档中的就绪检查，确认 PostgreSQL、backend 和 auto-submit worker 正常。
- [ ] 从应考人员设备确认管理、运维、就绪详情、文档和 OpenAPI 路径不可访问。

回传证据：候选入口、操作员入口、就绪检查结果，以及异常路径的 HTTP 状态。

### 真实手机与邮箱

- [ ] 使用真实手机浏览器，通过邮箱 OTP 登录并进入已受邀考试。
- [ ] 答题后刷新，确认答案保留。
- [ ] 断开网络后修改答案，恢复网络后确认草稿同步且没有覆盖更高服务器修订。
- [ ] 完成一次手动交卷，并在短时测试考试中验证到时自动交卷。
- [ ] 记录页面或按钮异常；不要使用共享验证码、人工 token 或登录后门。

回传证据：手机型号/浏览器、登录、刷新恢复、断网同步、手动交卷、自动交卷和异常描述。

### Mac 重启

- [ ] 在没有进行中考试时正常重启 Mac 并登录 designated host account。
- [ ] 等待 Docker Desktop 自动启动，不手动执行启动命令，观察平台入口恢复。
- [ ] 重新打开手机入口和操作员入口，确认重启前成绩仍在。

回传证据：Docker 是否自动启动、平台恢复用时、是否执行手动命令、两个入口状态和成绩是否保留。

## 每场考试前复验

- [ ] Mac、网络和 Docker Desktop 保持运行，当前最小 Compose 实例是唯一写入实例。
- [ ] 真实邮箱验证码可投递，考试配置、冻结名单、开放时间和邀请状态已核对。
- [ ] 没有 `in_progress` attempt 时才执行结构调整；考试开始后不改题、不改已发布名单、不升级、不删除持久卷。
- [ ] 结果解析只在全部 attempt terminal 后一次性发布；成绩和报表导出按需回读。

日常操作细节见 [`docs/exam-day-guide.md`](exam-day-guide.md)，不要在本页复制操作手册。

## 当前明确未启用

以下项目没有作为本次上线证据，也不能写成“已通过”：

- 发布包签名、RSA 密钥托管和 signed-release 安装；
- PostgreSQL 与学习媒体的配对备份；
- 独立加密第二副本；
- 隔离恢复演练、数据恢复和已验证回滚；
- 100-client 容量门禁（后续复验合同见 [`capacity-gate.md`](capacity-gate.md)）。

当前部署不提供已验证的数据恢复路径；保留旧镜像不等于可以回滚数据库。不要执行
`docker compose down --volumes`。

## 后续需要时再复验

- [ ] 使用另一台真实桌面浏览器和另一台真实手机，重复邮箱 OTP、考试开始、刷新恢复、提交和结果查看。
- [ ] 使用新鲜 OTP 从第二台设备接管，确认旧设备保存返回会话冲突，且快照、已保存答案和截止时间不变。
- [ ] 若人数、宿主资源或网络条件改变，按 [`capacity-gate.md`](capacity-gate.md) 重新执行隔离容量测试。
- [ ] 若需要备份、恢复、升级、跨主机迁移或公网/跨网访问，先停止当前考试并重新设计和验收对应的运维与安全边界。

## Stop Conditions

发生以下任一情况，立即停止新考生进入或暂停考试：候选入口无法访问；操作员入口从局域网可访问；数据库、backend 或 auto-submit worker 不健康；真实 SMTP 失败；答案刷新或断网恢复丢失；旧设备仍可在接管后保存；考试快照、冻结名单或成绩发生未授权变化；需要通过删除持久卷、共享验证码、人工 token 或临时第二写入实例恢复服务。
