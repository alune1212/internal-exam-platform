# Requirements

## 项目定位

公司内部临时考试与刷题平台，用于短期组织考试、练习刷题和查看基础考试报表。系统不是完整 LMS，不承担课程管理、复杂权限、消息队列或多租户能力。

## 角色与操作边界

- 用户：通过规范化邮箱申请六位邮件验证码；首次验证后在独立步骤填写显示名称即可创建账号。active 用户可学习、练习和复习错题，四小时 session 不提供“记住我”。
- 应考人员：只有被加入并冻结到某场考试的 per-exam roster 才能发现、开始、恢复或读取该场正式考试；平台显示名称编辑不会改写冻结名单或历史报表。
- 主操作员：在当前 macOS 正式宿主本地导入题库/名单、配置与发布考试、处理事件、查看报表、备份和关闭会话。
- 管理端可通过 `GET /api/admin/exams/{exam_id}/workspace` 查看单场考试的聚合运营工作区（发布就绪、名单/邀请/出席/attempt/incident 摘要和一个 advisory next action）；工作区不返回名单 PII，next action 不是授权依据。
- 备份操作员：与主操作员权限相同，账号默认禁用，仅在主操作员不可用时接管；两人不得同时操作。
- 操作员可以作废异常 attempt，并通过“预览 + 精确确认”批量发放补考；不得删除快照或审计证据。

第一版不实现复杂 RBAC。

### 账户与登录

- `POST /api/candidates/login` 是统一的邮箱入口，输入只包含邮箱；邮箱按 trim + lowercase 规范化，不能通过姓名、员工号、手机号后四位或旧名单字段登录。
- 验证码为六位数字，十分钟有效、单次使用、最多五次校验；重新发送冷却 60 秒，并同时执行每邮箱、每来源和全局发送限制。响应和错误不得枚举账号是否存在。
- 已完成且 active 的账号验证成功后获得最多四小时 `X-Candidate-Token`；新邮箱或 pending 账号只获得短时、单次的注册完成凭据，必须填写非空显示名称后才创建/激活账号并签发 token。inactive 账号保持邮箱唯一，验证后返回账号不可用，不得绕过管理员重新激活。
- 账户状态为 `pending`、`active`、`inactive`。用户只能编辑显示名称；规范化邮箱只读，不提供改邮箱、密码、物理删除或“记住我”。管理员可在 loopback 管理入口搜索并对已完成账号执行 active/inactive 切换，不能把 pending 直接强制激活。
- 学习、练习和错题复习只要求 active 账号；正式考试仍要求对应的 per-exam scope。邀请邮件只保留同源考试回跳路径，不携带 token、验证码、邀请码或授权凭据。

## 部署与服务等级

- 当前正式主机使用 Apple Silicon macOS + Docker Desktop + Docker Compose，单机 24×7 best-effort 运行，不建设高可用；严重主机故障允许暂停或改期。未来 Windows Docker Desktop + WSL2 只作为迁移目标，必须完成真实 Windows staging/UAT 后才能接管。
- Docker Desktop 由登记的 designated host account 运行；可以复用现有受管账号，不强制新建账号。正式根目录必须在工作树外、owner-only（目录 0700、环境文件 0600）。
- Docker Desktop 必须启用登录后启动、关闭 Resource Saver，资源固定为 8 CPU/8 GiB。Docker Desktop 当前没有按 Compose project 排除 Resource Saver 的正式合同；不得以不存在的 “formal exclusion” 代替关闭设置。正式 MacBook 考试期间必须接入 AC，电池不作为正式电源方案。
- 正式应考人员入口使用网络管理员批准并完成 DHCP reservation 的 `<FORMAL_LAN_IP>/24`；pf/受管防火墙只允许已批准的局域网 CIDR 到 `<FORMAL_LAN_IP>:8080`，操作员入口严格只绑定 `127.0.0.1:8081`。`<FORMAL_LAN_IP>` 是唯一规范占位符；历史或 synthetic UAT 中出现的具体地址不得复制到正式配置。
- 应考人员入口在现有办公局域网使用 HTTP 8080，并记录为明确接受的第一阶段安全例外；不得把该入口描述成传输安全。
- 普通办公设备、应考人员电脑和手机共用现有局域网，不假设独立路由器、专用 Wi-Fi 或受管终端。不得把 HTTP 描述为传输安全。
- 正式 admin/candidate token 有效期固定 4 小时；单场考试最长 2 小时；考后全局关闭会话。
- 前端运行时完全离线，自托管全部静态资源，不访问公共字体、CDN 或遥测服务。
- 正式宿主、开发项目和 staging 项目必须使用不同 Compose project/volume；考试窗口内停止开发和 staging，任何时刻只允许一个 formal writer。
- 不做完整防作弊/监考，不隔离练习题与正式题库，也不以阻止题库泄露为第一阶段目标。

## 题型

第一版只支持：

- `single`：单选题
- `multiple`：多选题
- `judge`：判断题

不支持问答题、填空题、简答题、案例分析题。

## 练习模式

- 可刷全部 `active` 状态题目。
- 不计入正式成绩。
- 题目列表在提交前不返回正确答案或解析；每次提交后立即返回对错、标准化正确答案、选项对比和解析，并锁定本次反馈。
- 重新练习会新增不可变的 `practice_answer` 记录，不覆盖先前结果。
- 错题复习仅展示当前用户的历史，支持按一级/二级分类和掌握状态筛选；最后一次练习答对时标记“已掌握”，但保留早期错误记录。

## 视频学习

- 视频学习是独立功能，不绑定考试资格、考试开始、交卷、判分、排名或练习。
- 管理员在管理后台本地上传 `mp4` / `webm` 学习视频，系统保存视频元数据和不透明 storage key。
- 上传视频默认为 `draft`，发布为 `published` 后所有 active 用户可在学习页看到；归档后不再展示给用户。
- 用户观看视频时，系统记录最后播放位置、已观看区间、完成百分比和最近心跳时间。
- 单次心跳的可计入观看区间有上限，重复播放和拖动跳转不能虚增完成度。
- 完成阈值固定为 90%；达到阈值后记录 `completed_at`。
- 学习完成状态只用于学习报表，不影响考试 active 列表、考试 start/submit、成绩、排名或练习记录。

## 考试模式

- 用户通过统一邮箱 OTP 登录；应考人员只在对应考试 roster scope 内可见和进入正式考试。已发布且已受邀的考试会立即显示 `available_from`，但到时间前仍不能开始。
- 开始考试时按考试配置生成题目快照。
- 默认考试配置使用固定 50 题试卷，总分 100 分，及格线 60 分。
- 固定 50 题试卷当前配比为 30 道单选、10 道多选、10 道判断。
- 固定试卷需覆盖 active 题库中的知识点、题型，以及存在库存的知识点 + 题型组合。
- 固定试卷中相同题干只出现一次，避免重复导入题目在同一张试卷中重复出现。
- 固定试卷按总分和题量均分为整数分值，例如 50 题 100 分时每题 2 分；不能整除时余数分配到前若干题。
- 同一场考试为应考人员生成符合相同规则的等价试卷，并以 attempt snapshot 固化复核依据。
- 正式考试以题目快照为准。
- 考试中自动暂存答案。
- 暂存不是暂停，倒计时继续。
- 允许提前交卷。
- 到最后一道题时，主操作按钮显示“交卷”，不再显示禁用的“下一题”。
- 到时间自动交卷。
- 交卷后自动判分。
- 交卷后立即显示分数和通过状态；答案与解析只能在全部记录结束后由操作员手动、一次性发布。
- 交卷后显示通过 / 未通过状态。
- 排名仅管理员可见。
- 管理员授权补考后，应考人员可重新进入该考试并生成新的等价试卷 attempt。
- 邮箱登录不受旧的 30 分钟名单登录窗口限制；新开考仍在 `available_from` 前拒绝，开考后 15 分钟停止新建 attempt，宽限内开始仍获得完整时长。
- 同一 attempt 只允许一个活动设备会话；新鲜 OTP 接管后旧设备保存必须失败。
- 网络中断时允许 session-scoped 本地临时草稿，恢复后按修订号同步；草稿不暂停倒计时。答案草稿和短时凭据只在当前浏览器标签页的 `sessionStorage` 中保留，同一标签页 reload 可恢复；关闭标签页/窗口、换标签页、换设备或跨宿主迁移不保证恢复，需重新 OTP 登录或既有 takeover 流程。

## 生命周期与运维

- 数据默认保留 12 个月，采用自动提醒、人工确认删除的两阶段流程；无固定到期复审。
- 每日按数据变化机会式备份，考试前后人工强制备份；备份短暂冻结写操作。本机只保留最近三份验证副本，post-exam 同步到独立加密第二存储并保留 12 个月。
- 首次发布及每季度从第二副本执行一次性隔离恢复演练。
- 上传/升级前动态磁盘水位为操作后至少 20 GiB 且不少于三倍占用；不能因此阻断正式答题保存和交卷。
- 服务可自动恢复，但必须人工确认预检后开考。正式发布后冻结七天；没有固定维护窗口，季度维护按需安排。
- 开考后进入只读运维窗口，全部交卷后恢复管理写操作。
- 日志本地轮转；一键诊断包只包含有界、脱敏、带 checksum 的状态和日志。
- 唯一标准回滚路径是上一版本发布包 + 升级前配对备份。

## 判分规则

- 单选题：用户答案与正确答案一致得分。
- 判断题：用户答案与正确答案一致得分。
- 多选题：用户选择集合与正确答案集合完全一致才得分。
- 多选比较按集合，不按字符串顺序。例如 `A,C` 与 `C,A` 判定为正确。

## 第一阶段原始交付边界

第一阶段原始目标是先完成可运行框架，不一次性完成全部业务：项目结构、后端 app、前端 app、模型、迁移、基础路由、页面骨架、Docker Compose、文档和健康检查。当前完成状态以 `docs/handoff.md` 为准。
