# 第一阶段局域网 HTTP 安全例外

## 当前范围

当前正式运行实例是本机最小部署，应考人员入口固定为
`http://192.168.2.225:8080`，操作员入口固定为 Mac 本机的
`http://127.0.0.1:8081/admin/login`。入口位于受控办公局域网，使用 HTTP 是当前第一阶段明确接受的安全例外；它没有传输加密、服务器身份认证或抗中间人保护，不能称为“安全 HTTP”“内网 HTTPS”或“等同 HTTPS”。

HTTP 上可观察或被篡改的数据包括：用户 bearer token、显示名称/邮箱/部门等页面数据、邀请目标、考试列表、题干与选项、作答请求、成绩和已发布解析、练习记录、学习内容与进度。SMTP 邮件仍按受保护 `formal.env` 中的 TLS 配置传输，但用户输入验证码后的 Web session 位于 HTTP。能控制或监听办公网、网关、恶意接入点或已感染终端的攻击者可能窃取 token、冒用会话、读取题目或修改请求。

## 当前已验证的控制

- 操作员只在 Mac 本机通过 `127.0.0.1:8081` 操作；候选入口不会公开管理、运维、就绪详情、文档或 OpenAPI 路径。
- PostgreSQL、backend 和 direct frontend 端口不作为候选入口暴露；候选流量只经过 8080 网关。
- 登录使用六位、十分钟、单次邮箱 OTP；每邮箱、每来源和全局窗口均限流，SMTP 故障 fail closed，不提供共享验证码、人工 token 或管理员登录后门。新邮箱必须完成显示名称步骤，inactive 账号不能借 OTP 创建替代身份。
- 四小时 candidate token 只存于 session-scoped 浏览器状态，不提供 remember-me；邀请 URL 只保留同源回跳路径，不携带 token、OTP、邀请码或 scope 授权。
- 正式答题草稿沿用当前标签页的 `sessionStorage`：同一标签页 reload 可恢复并按 answer revision 同步；关闭标签页/窗口、换标签页、换设备时不保证恢复，必须重新 OTP 登录或显式 takeover。该边界不提供 durable offline credentials。
- 正式 attempt 只允许一个活动设备会话；新设备必须以新鲜 OTP 显式接管，旧设备保存立即失败。
- 前端静态资源全部自托管，运行时不访问公共 CDN；日志和诊断不记录 OTP、token、密码、SMTP secret 或完整邮箱。
- 本次上线的真实邮箱、设备、答题和 Mac 重启验收证据见 [`docs/handoff.md`](handoff.md)；本页不重复记录设备型号或逐项结果。

这些措施降低暴露面，但不消除同网段监听、ARP/DNS 欺骗、终端恶意软件或 HTTP 内容篡改风险。当前最小部署不启用发布包签名、配对备份、独立第二副本或恢复演练；这不是传输安全或数据恢复承诺。系统也不建设完整防作弊或监考能力，题库泄露不在第一阶段阻断目标内。

## 事件触发的重新评估

发生以下任一事件时，必须停止扩大当前 HTTP 暴露并重新评估 HTTPS、网络隔离或部署方式：入口需要跨网段、VPN 或公网访问；应考人员或考试频率明显扩大；公司能提供域名、子域名或证书；办公网出现监听、恶意接入点、会话劫持或终端感染事件；考试内容或个人数据敏感等级提高；法律、审计或公司安全政策要求加密传输；当前 Mac 地址或受控网络边界无法持续证明。

重新评估完成前不得扩大当前 HTTP 暴露范围。若具备域名与证书，应切换到 HTTPS；不要要求应考人员忽略证书警告，也不要临时开放公网入口。
