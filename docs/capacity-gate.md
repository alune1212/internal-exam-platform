# 100 客户端容量门禁（后续复验）

当前正式运行是面向少量人员、偶发考试的单 Mac 最小部署。已完成的上线验收范围和证据见 [`handoff.md`](handoff.md)；它没有证明持续 100 人并发，也没有把容量门禁作为本次上线条件。

当考试规模、宿主资源或网络条件改变时，再在与当前数据隔离的临时 Compose 项目运行：

```bash
./ops/e2e/run-capacity-gate.sh
```

门禁固定创建 100 个使用规范化邮箱的隔离 active 账号/应考 scope，并同时执行开始考试、修订号保存和交卷。fixture 不使用姓名、旧人员字段或全局出席标记作为身份；正式 report/roster identity 只来自 per-exam scope。通过条件为：请求错误数为 0、100 份记录全部交卷、开始/保存/交卷的 P95 分别不超过 5000/2000/3000 ms、测试期间数据库连接数不超过 40、worker 心跳不超过 90 秒。结果和 SHA-256 写入 `.runtime/e2e/evidence/`；失败时命令返回非零，不得把结果写成正式上线证据。

开考门限包含固定试卷快照创建成本，按 100 人同时点击的突发场景设为 5 秒；保存和交卷仍保持更严格门限。门限不通过时不能增加数据库连接数或临时关闭限制来换取通过。

本门禁只回答容量问题，不证明发布签名、备份、独立第二副本、恢复演练或高可用。当前最小部署明确未启用这些能力；若将来启用完整运维路径，必须重新绑定实际 Mac、镜像版本和配置并保存可复核证据。
