## Context

范围已由访谈与 ADR-0001 确认，动机见 proposal.md。CI 仍解析完整 Mac/Windows 脚本并生成 Windows 发布包；Python 备份工具同时被运维 API、迁移保护和 E2E 使用，不能随外层脚本整目录删除。

## Goals / Non-Goals

**Goals:** 沿依赖关系删除未采用的运维入口及专用检查，保持当前业务与安全检查；实现可追溯的源码发布。

**Non-Goals:** 数据模型迁移、鉴权改造、新发布框架、离线镜像包、正式主机变更。

## Decisions

- 删除 ops/macos 和 ops/windows 的历史入口及专用合同测试，保留 ops/security、ops/e2e、Python 共享工具及其有效测试，避免削弱现行防护。
- 使用既有 skipped 状态表示没有备份产物，并说明恢复能力未验证；已有产物验证失败或读取异常仍显示 failed。无需新配置开关或更改 API 结构。
- 更新现有版本声明与锁文件，FastAPI 文档版本复用运行配置；不增加版本生成层。
- 使用现有 CI、Git 标签和 GitHub Release 完成源码交付，不建设新发布流水线。旧活动变更按实际退出范围说明并保留未完成项，当前规格先同步再处理归档。

## Risks / Trade-offs

- 历史脚本有残留调用 → 搜索全部非归档引用，执行保留的部署、安全、数据库与浏览器检查。
- 无备份被误认为安全 → 状态明确恢复未验证，坏产物仍报错；保留鉴权和数据保护。
- 源码发布被误作生产验收 → handoff 保留现网提交，发布说明明确未升级主机。

## Migration Plan

无数据库迁移。完成当前候选的工程验证、隔离回归、CI 和必要依赖检查后，发布源码标签与说明；线上部署另行安排。
